# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev        # Dev server on port 3000
pnpm build      # Production build (Vite + Nitro)
pnpm preview    # Preview the production build
pnpm test       # Vitest (no test files exist yet — see Testing)
pnpm lint       # Biome lint
pnpm format     # Biome format
pnpm check      # Biome lint + format
```

Always use **pnpm**, never npm or yarn.

There is no `typecheck` script; run `npx tsc --noEmit` directly.

## Architecture

**Stack:** React 19, TypeScript, TanStack Start (SSR meta-framework on Vite), TanStack Router (file-based), Tailwind CSS v4, i18next, motion (Framer Motion v12), Biome, Vitest.

### Routing

Two routes only, in `src/routes/`:

- `__root.tsx` — document shell, `<head>` meta/links, `MotionConfig`
- `index.tsx` — the single landing page

`src/routeTree.gen.ts` is generated by TanStack Router — **never edit it manually**.

### Page structure

`index.tsx` composes one page from flat section components in `src/components/`:

`Navigation → Hero → Experience → Skills → Projects → Contact → Footer`

Section `id`s are `top`, `work`, `stack`, `projects`, `contact`. `Navigation`'s
`NAV_ITEMS` array references these ids — **if you rename a section id, update
`NAV_ITEMS` too** or the scroll-spy and anchors silently break.

Static content lives in `src/data/` (`experience.ts`, `skills.ts`, `projects.ts`)
so components stay presentational. All user-facing strings live in i18n.

## Design system — "Ledger"

Tailwind v4, so there is **no `tailwind.config.ts`**. Every token is a CSS
variable in the `@theme` block of `src/styles.css`.

White paper, `#111` ink, one burnt-amber accent (`#b45309`). Hierarchy comes
from **weight and 2px rules, never from colour fields**. Corners are square
(`--radius-*: 0px`) and there are deliberately **no shadow tokens**.

Type is **Archivo** (display + UI, variable 400–800), **Instrument Sans**
(running body copy), **IBM Plex Mono** (micro-copy: labels, meta, chips).

Always style through semantic tokens — `bg-paper`, `text-text-muted`,
`border-rule-strong`, `text-meta` — not raw Tailwind palette classes like
`bg-slate-800` or `border-white/5`. A stray raw class is the main way this
design drifts.

### Fonts

Self-hosted in `public/fonts/`, declared with hand-written `@font-face` in
`styles.css`. **Do not reintroduce a Google Fonts `@import`** — it costs three
serial round trips before any text paints.

The `latin` subset covers all Portuguese diacritics (they live in U+00C0–00FF).
`latin-ext` is declared only so Central/Eastern European glyphs degrade
gracefully; it never downloads for pt/en.

Only above-the-fold faces are preloaded in `__root.tsx` (Archivo + Plex Mono).
Preloading every face makes things slower, not faster.

## i18n

Portuguese is the default, English secondary. Files: `src/i18n/locales/pt.json`
and `en.json`, flat namespace under `translation`.

**Any new user-facing string must land in BOTH files.** This includes
`aria-label`s — they go under the `a11y.*` namespace, never hardcoded English
in JSX.

Constraints that are easy to break:

- `lng` in `src/i18n/config.ts` must stay a constant (`"pt"`) and match
  `<html lang="pt">` in `__root.tsx`, or SSR and first client render disagree
  and React warns about hydration.
- The stored preference is restored **after hydration**, inside a `useEffect`
  in `LanguageSwitcher`. Never read `localStorage` during render.
- Bullet lists come back via `t(key, { returnObjects: true }) as string[]`.

## Accessibility and motion

Reduced motion is handled in three layers — keep all three:

1. A blanket `@media (prefers-reduced-motion: reduce)` block in `styles.css`.
2. `<MotionConfig reducedMotion="user">` in `__root.tsx`, which makes every
   `motion` animation respect the OS setting without per-component work.
3. `usePrefersReducedMotion()` (`src/hooks/`) for imperative cases only — the
   hero video gate and `scrollIntoView` behaviour. It is SSR-safe via
   `useSyncExternalStore`; **never call `matchMedia` at module scope**, it
   throws during SSR.

The hero `<video>` deliberately has **no `autoPlay` attribute** — deriving it
from a media query causes a hydration mismatch. Playback is driven by an
`IntersectionObserver` in `Hero.tsx`, which also keeps `preload="none"` honest
so the video never competes with the LCP text.

The `<h1>` is the LCP element and is intentionally **not** animated from
`opacity: 0`.

## Media

- `public/media/hero.mp4` — full-bleed 24:9 masthead band.
- `public/media/hero-poster.jpg` — the video poster. Reduced-motion users never
  trigger playback, so this is what they see; it must always exist.
- `ffmpeg is not installed.` To regenerate the poster, load the mp4 in a
  browser, seek, `drawImage` to a canvas and `toBlob`.
- Experience cards and Projects take optional screenshots (`image` /
  `media`); both fall back to a captioned placeholder, so nothing breaks
  when the asset is missing.

Generated images are 1k PNGs. `sharp` is a devDependency for converting them
to WebP; it is build-time only and must not be imported at runtime.

## Testing

`vitest`, `jsdom` and Testing Library are installed and `pnpm test` is wired
up, but **no test files exist** and `vite.config.ts` has no `test` block or
jsdom environment configured. Adding the first test means configuring that
first. `usePrefersReducedMotion` and the i18n key parity between `pt.json` and
`en.json` are the highest-value things to cover.

## Code quality

Biome handles lint and format: double quotes, tab indent, automatic import
organisation. `routeTree.gen.ts` and `styles.css` are **excluded** in
`biome.json` — so `pnpm check` will not catch CSS mistakes; review
`styles.css` by eye.

## Path alias

`@/*` maps to `./src/*`. Use it for all internal imports.
